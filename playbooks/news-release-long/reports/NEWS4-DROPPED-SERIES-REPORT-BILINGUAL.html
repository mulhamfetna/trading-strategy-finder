L3 Method, the bug the control caught, traps for the future, and what stays open · المنهج والفخاخ وما بقي مفتوحًا

The discipline that held

  • Pre-registration before every run — N2 (a988f17) and N3 (70f29fc) committed with tests, alphas, the $150 powered-null line and blind spots frozen before results existed. Nothing drifted afterwards.
  • The verdict ladder: jump gate first (a block whose minute doesn’t move price gets VOID-TIMESTAMP, never “no premium”); then t-test → chronological half-split → quiet-day floor → 1,000-placebo noise check; negatives split into POWERED-NULL (MDE ≤ $150) vs UNDERPOWERED (“cannot tell” — never dressed as “no”).
  • V1/V2/V3 + claims ledger: 6 new claims, 18 checks, each triple failing for a different reason — suite 33/33 green on the local machine and the server.
الانضباط الذي صمد: تسجيل مسبق قبل كل تشغيل (بالاختبارات والعتبات والنقاط العمياء مجمّدةً قبل وجود النتائج)؛ سلّم أحكام يبدأ ببوابة القفزة (الكتلة التي لا تحرك دقيقتُها السعرَ حكمُها «طابع باطل» لا «لا عائد»)؛ ثم اختبار t فنصفا التاريخ فأرضية الأيام الهادئة فمحاكاة الضجيج؛ والسلبيات تنقسم إلى «صفر مُقوّى» أو «غير مُقوّى — لا نستطيع الجزم» ولا تُلبَس أبدًا ثوبَ «لا». وسجلّ الادعاءات: 6 ادعاءات جديدة و18 فحصًا، والحزمة 33/33 خضراء محليًا وعلى الخادم.

⭐ The bug the positive control caught — the day’s best save

What happened: the first cut of the quiet-day gate was coded two-sided. The 08:30 quiet-day ride is itself significantly negative (≈ −$50 net — cost drag plus quiet-morning drift), so the gate wrongly vetoed CPI itself (verdict FAILED-GATES on a p=2.8e-05 positive!). The pre-registration’s wording — the control must not itself show a positive premium — was right; the code was wrong. Fixed to the registered wording (commit 778492c), every scan re-run after the fix, thresholds untouched. Without the positive control this bug would have silently hardened the “zero” story.
⭐ الخطأ الذي اصطاده الضبطُ الموجب — أفضل إنقاذ في اليوم: النسخة الأولى من بوابة الأيام الهادئة كُتبت ثنائية الاتجاه، وركوبُ الأيام الهادئة عند 08:30 سلبيٌّ معنويًا بذاته (≈ −$50 صافيًا: سحبُ تكاليف + انجراف صباح هادئ)، فرفضت البوابةُ خطأً CPI نفسه رغم p=2.8e-05! صياغة التسجيل المسبق كانت صحيحة («يجب ألا يُظهر الضابطُ عائدًا موجبًا») والكودُ هو الخاطئ. أُصلح إلى الصياغة المسجلة وأُعيدت كل عمليات المسح بعد الإصلاح دون مسّ أي عتبة. لولا الضبط الموجب لتصلّبت قصةُ «الصفر» على خطأٍ صامت.

Traps recorded for every future calendar study

  • Initial Jobless Claims carries TradingView importance 0 — any importance≥1 filter silently drops the single highest-frequency macro release (556 usable events).
  • Title renames split series: ISM Non-Manufacturing↔ISM Services, Markit↔S&P Global, “4-Week”↔“4-week”. Without the merge map a series loses half its history invisibly.
  • The scan unit is the MINUTE, not the title — the NFP minute carries up to 19 co-released titles; counting titles double-counts moments.
  • Window overlap: a 12:15 ADP ride is still open at a 12:30 CPI print — without the overlap exclusion, CPI’s premium leaks into ADP’s measurement.
  • Read gross next to net before narrating any “significant negative” — on a $22.50 cost line, low-variance instruments make pure cost drag look like an anti-premium.
  • Server venv facts: data_2010_1s/venv needed scipy via python3 -m pip (the pip binary is broken), and the blanket-gitignored evidence CSVs (forecast_previous_*, alfred_revision_*) had to be copied for the ledger to go green there.
