# WS-AS — Action Plan

**Goal:** 6 delivery bundles (one per instrument) that mirror `NQ_SIGNALS_DELIVERY`, candles matched
to their own boxes, NQ regenerated byte-identical. Built test-first; nothing in `subprojects/signals/`
math changes — it is parameterized and reused.

**Gating decisions — RESOLVED (ANALYSIS §5):** D1 = follow NQ roll uniformly (futures hour≥18 for
ALL instruments incl. ETFs); D2 = weekly+monthly only (no daily); D3 = evaluated in AS.6. Net: every
instrument uses the **identical frozen code path**; only instrument identity (paths + token) varies,
so NQ parity is byte-identical by construction and AS.2 reduces to a thin reuse wrapper (no seams).

---

## Phase AS.0 — Subproject scaffold ✅ (this step)
`subprojects/all-stocks-signals/` with `docs/{ANALYSIS,DATA_MAP,PLAN}.md`. README + `__init__` to
follow in AS.1.

## Phase AS.1 — Instrument config registry (the no-mix contract)
A single declarative table `instruments.py`: per token → `{candle_dir, candle_prefix, box_csv,
roll_rule, level_families}`. This is the *only* place paths/instrument identity live, so
cross-instrument mixing is impossible by construction.
- **Test:** every config resolves to existing files for all 7 TFs; box `Date` range ⊇ candle range
  (loud failure otherwise); the 6 tokens are exactly the expected set.

## Phase AS.2 — Thin reuse wrapper (NO seams needed; D1/D2 = NQ logic)
Because every instrument uses the identical roll + levels, **no parameterization of the frozen rule
is required**. Reuse verbatim:
- `generate_stage1.generate(candles_csv, boxes_csv)` (or `_emit_rows` for the per-preset year filter,
  exactly as `generate_full_candles.stage1_for_preset` already does) — same `BoxLookup` roll, same
  `_WEEKLY_LEVELS + _MONTHLY_LEVELS`.
- `generate_stage2.generate(stage1_df)` — verbatim.
The instrument only supplies **paths + output token**. `generate_stage1.py` is **not modified**.
- **Test:** the driver's Stage 1 for NQ reproduces `generate_stage1.generate` exactly on a sample
  (sanity before the full AS.4 byte-parity gate).

## Phase AS.3 — Per-instrument driver
Generalize `generate_full_candles.run_timeframe` to take an instrument config: iterate its 7 TFs × 3
presets, write all-signals / holds-dropped / reverse / by_direction + per-instrument `SUMMARY.csv`,
using the config's roll + levels. Output token = the instrument token (e.g. `QQQ-ETH_15m_2025.csv`).
- **Test:** small synthetic instrument (a handful of candles + a 2-row box) yields the hand-computed
  signals under both roll rules — proves the roll seam actually changes ETH 18:00/19:00 mapping.

## Phase AS.4 — **NQ parity gate (HARD anchor)**
Run the new driver for `NQ` only and diff every file against the committed `NQ_SIGNALS_DELIVERY`.
Must be **byte-identical** (all-signals + reverse for all 7 TF × 3 presets). This proves the
generalization didn't perturb the frozen path. **Blocks AS.5 until green.**

## Phase AS.5 — Generate the 5 new bundles
Run ES, QQQ-RTH, QQQ-ETH, SQQQ-RTH, SQQQ-ETH. Package each into `<INSTR>_SIGNALS_DELIVERY/` with the
4 numbered folders + README (instrument-stamped) + SUMMARY, mirroring the NQ packager. Optional zip
per bundle.
- **Validation per bundle:** SUMMARY sanity (long+short+hold = signal_rows; no_hold = long+short;
  reverse ≤ no_hold); every `box_id` date ∈ the instrument's own box index; holds-dropped ⊂
  all-signals; by_direction partitions reverse exactly.

## Phase AS.6 — Parallel execution (D3)
The work is embarrassingly parallel — each instrument is independent. Design:
- **Grain:** instrument (6 workers) or instrument×TF (42 tasks) for finer balance; 1m presets are the
  long poles, so scheduling 1m tasks first improves makespan.
- **Local:** Python `multiprocessing`/`ProcessPoolExecutor`, N = cores−2; CPU-bound (pandas), so GPU
  is irrelevant. Memory watch: NQ/ES 1m `full` Stage-1 streams are multi-million rows — cap
  concurrent 1m jobs to fit RAM.
- **Server:** the training box (`subprojects/meta-prophet/server/`) gives more cores/RAM; same code,
  rsync inputs ↔ outputs. Choose at launch.
- Deterministic regardless of worker count (no shared state, stable sort).
- **Report:** wall-clock + makespan per grain so we can pick local vs server with numbers.

## Phase AS.7 — Final docs + reports + commit
Per-bundle README, a top-level `REPORT.md` (counts table across all 6 instruments, parity evidence,
timings), update progress tracker; commit. Bundles/zips git-ignored if large (mirror how
`NQ_SIGNALS_DELIVERY.zip` is currently untracked) — confirm at commit time.

## Test/▪parity ladder (what proves correctness)
1. config resolves + coverage (AS.1) → 2. wrapper == frozen Stage 1 on NQ sample (AS.2) →
3. synthetic roll-rule divergence (AS.3) → 4. **full NQ byte-parity** (AS.4) → 5. per-bundle
structural validation (AS.5). No bundle ships before its structural checks pass; nothing ships before
NQ parity is green.

## Risk register
| Risk | Mitigation |
|---|---|
| Refactoring frozen `generate_stage1` perturbs NQ | defaults preserve behavior + AS.4 byte-parity gate; copy-fallback if needed |
| D1 chosen wrong for ETH | synthetic test makes the 18:00/19:00 remap explicit and reviewable before full run |
| RAM blow-up on 1m `full` | cap concurrent 1m jobs; stream/iterate as the frozen code already does |
| Output token collision (QQQ/SQQQ RTH vs ETH) | tokens include the session variant; AS.1 asserts uniqueness |
| Box/candle range mismatch for an instrument | AS.1 coverage assertion fails loudly (already pre-verified clean) |

## Definition of done
6 `<INSTR>_SIGNALS_DELIVERY/` bundles, NQ byte-identical to the committed delivery, every bundle
passing structural validation, a timings+counts report, docs updated, committed.
